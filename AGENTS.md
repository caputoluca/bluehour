# Blue Hour — maintainer notes

One theme, one JSON, no build step (single variant → plain JSON; one variant needs no generator). Source of truth is `themes/blue-hour-color-theme.json`; `palette.json` names the roles.

- **Layout:**
  - `package.json` (manifest, one `contributes.themes` entry) · `themes/` · `palette.json` (the vocabulary) · `README.md` (public, the listing page) · `design-notes.md` (the record: versions, what was tried, sources) · `CHANGELOG.md` (what shipped when, packaged into the `.vsix`).
  - `samples/`: the dev-host workspace. It pins the theme and turns the TypeScript checker and Biome off, because the samples import files and packages that exist nowhere and the window filled with unresolved-import errors; take the two lines out of its `.vscode/settings.json` to judge the squiggle colors. `blue-hour.ts` is the hero's code.
  - `assets/` (`logo.svg` is the source; `hero.png` and `icon.png` are rendered from it, never edited) · `tools/colortool.py` (OKLCH / WCAG / APCA checker) · `tools/check.py` (drift check: palette ↔ theme ↔ README table ↔ token rule names ↔ logo) · `tools/hero.mjs` (renders the hero and the icon from the pages in `tools/hero/`) · `pyproject.toml`, `biome.json`, `.husky/` (the lint gate and the commit hook, dev only, kept out of the `.vsix`) · `.vscode/launch.json` (F5).
  - `builds/` (ignored, like every `.vsix`): the package files built here. A new build lands in the root and moves in once it is released; those from 0.2.7 on are also on the GitHub releases, the five `blue-hour-theme-*` from before the rename exist only here.
- **Commands:**
  - F5 or `cursor --extensionDevelopmentPath="$PWD" "$PWD/samples"` to look; the pre-commit hook runs lint-staged (Biome, ruff, ty and basedpyright on the staged files) and `python3 tools/check.py`, and refuses the commit on a failure; `npm run lint` runs the whole gate.
  - `npm install` (it also installs the hook) and `uv sync` once, then `npm run hero` after any color or logo change: Shiki colors `samples/blue-hour.ts` through the theme file, headless Chrome exports `assets/hero.png` at 2x and `assets/icon.png`; it refuses to render without Geist Mono installed.
  - `npx @vscode/vsce package` to build a `.vsix`; `cursor --install-extension <file>.vsix` to install.
  - To tweak a role, find-and-replace its hex in the theme file and Cmd+R the dev-host window (edits usually apply live); `Developer: Inspect Editor Tokens and Scopes` on a word shows which rule colored it.
  - Before a publish, the leak check: with the theme active, run `Developer: Generate Color Theme From Current Settings`, and every commented-out line is a color still falling back to stock VS Code.
- **Rules:**
  - Every color is designed on the ladder and checked with the tool before it goes in — no eyeballed hex, no verbatim photo samples.
  - Red only for errors, invalid code, deletions and conflicts. No italics, and no bold in syntax except Markdown headings (rule 9); Markdown's own emphasis renders as written (rules 10 and 11).
  - The README is public and write-once (hero, a version badge under the title, one-liner, install, the system, the ladder, working on it, links, license: the shape shared by 21 public READMEs read 2026-09-28, where the badge stands in for their status line). Its prose is first person, from Luca's own reasons: each choice carries its why, nothing pitches or compares.
  - Prose is in American spelling, in every file; a paper's title keeps its published spelling.
  - The record goes to `design-notes.md` and `CHANGELOG.md`, and no quote, ticket id, craft path or working state goes into any of the three.
  - `walkThrough.embeddedEditorBackground` stays although Cursor's schema flags it in the theme file: Cursor dropped the walkthrough page, VS Code still registers the color (checked in microsoft/vscode, 2026-10-04).
  - This file's Open item is the pick-up point; the board is the roadmap.
- **Vocabulary (decided 2026-09-28):**
  - `palette.json` keys are the one set of names; the README ladder table's first column and the token rule names in the theme (`<what> — <key>[, note]`) follow them, and `tools/check.py` fails when the three drift. Why: three vocabularies named the same rungs, and the table had drifted eleven values behind the file (audited 2026-09-18).
  - Neutrals by rung, extending Rosé Pine's `muted`/`subtle`/`text` (the reference ladder; the sources are in `design-notes.md`): `ground`, `raised`, `hairline`, `muted`, `comment`, `subtle`, `frame`, `text`, `bright`.
  - Accents by color: `blue`, `sky`, `peach`, `gold`, `red`, `green`, `magenta` — the last exists only for the ANSI slot, the room has no purple. State backgrounds at the blue-hour hue: `highlight_low`/`_mid`/`_high`. Terminal brights: `<base>_bright`.
  - File order, which the table follows: neutrals and highlights by lightness, accents by family (cool pair, warm pair, then the status colors), brights in ANSI slot order.
- **Hero and logo (decided 2026-09-28, picks shown live):**
  - The hero is Vesper's card composition with a window frame like the other theme heroes' (rounded, hairline edge, three gray dots, the file name), on the theme's own ground, the code fading right and bottom, the lockup bottom right: `samples/blue-hour.ts` lines 1–33, the current line on `ceiling.off()`.
  - It is not a screenshot: `tools/hero.mjs` colors the sample with the theme's token rules and takes every chrome color from the theme's own keys, so a color change regenerates it with one command (of eleven theme repos read 2026-09-28, none keeps its hero current; the median is three years behind the source).
  - The logo is the dome: a blue-hour gradient through `highlight_low`, `highlight_high` and `blue` to the `sky` rung at the horizon, a `peach` horizon line that passes the dome by its round ends (the dome 96 wide of 128, the line 101), on the `ground` tile.
  - The source holds only the four rungs; `tools/hero.mjs` eases through them when it renders (a monotone cubic in OKLab), so `assets/logo.svg` opened on its own still blends straight from stop to stop. Every hex in `assets/logo.svg` is a rung; `check.py` fails otherwise. The wordmark says "Blue Hour"; regenerating is one command.
  - Redrawn 2026-10-04 (0.2.10) after it was seen large on the registry listing: the straight blend showed a line at each of the two middle stops, and the ground showed between the dome's corners and the line's round ends; two candidates shown side by side, the square-ended one passed over.
  - Rejected on sight: a bird's-eye plan of the room (charming at 128, dots at 16), a lightness-ladder mark (a menu icon at 16), a lamp-in-a-window mark; three JSX-heavy code stretches, which read as HTML; a full-window screenshot under the ladder (`design-notes.md` says why). If the frame is ever shown, it is a second render from `tools/hero.mjs`.
- **Publishing (the record of the name and the registries: `design-notes.md` § The name and the listings):**
  - The id `caputoluca.bluehour` is permanent. `contributes.themes[].id` is set to the label ("Id of the color theme as used in the user settings", per the extension point's schema in microsoft/vscode), so the label can change later without resetting users' `workbench.colorTheme`; it equals today's label, so existing settings keep matching.
  - One file per version, on both registries and in its GitHub release: `npx @vscode/vsce package`; `npx ovsx publish <file>` (Open VSX, the registry Cursor searches, with the token the tool stored at the first publish); the same file uploaded on the publisher page at marketplace.visualstudio.com/manage (Microsoft, no token); `gh release create <tag> <file>`.
  - Built before the reviewer's pass and uploaded only after it, so the three copies stay one file.
  - vsce rewrites the README's relative links to `raw/HEAD` and `blob/HEAD` URLs under `repository`, so they follow the default branch (`main`); `.vscodeignore` keeps `hero.png` and `design-notes.md` out of the `.vsix`.
  - The hero is the repo's social preview, an upload on GitHub's settings page, so it is set again whenever the hero changes.
