# Blue Hour — maintainer notes

One theme, one JSON, no build step (single variant → plain JSON, per the authoring brief in craft). Source of truth is `themes/blue-hour-color-theme.json`; `palette.json` names the roles.

- **Layout:** `package.json` (manifest, one `contributes.themes` entry) · `themes/` · `palette.json` (the vocabulary) · `samples/` (dev-host workspace, pins the theme; `blue-hour.ts` is the hero's code) · `assets/` (`logo.svg` is the source; `hero.png` and `icon.png` are rendered from it, never edited) · `tools/colortool.py` (OKLCH / WCAG / APCA checker) · `tools/check.py` (drift check: palette ↔ theme ↔ README table ↔ token rule names ↔ logo) · `tools/hero.mjs` (renders the hero and the icon) · `.vscode/launch.json` (F5).
- **Commands:** F5 or `cursor --extensionDevelopmentPath="$PWD" "$PWD/samples"` to look; `python3 tools/check.py` before a commit; `npm install` once, then `npm run hero` after any colour or logo change (Shiki colours `samples/blue-hour.ts` through the theme file, headless Chrome exports `assets/hero.png` at 2x and `assets/icon.png`; it refuses to render without Geist Mono installed); `npx @vscode/vsce package` to build a `.vsix`; `cursor --install-extension <file>.vsix` to install.
- **Rules:** every colour is designed on the ladder and checked with the tool before it goes in — no eyeballed hex, no verbatim photo samples. Red only for errors and deletions. No italics. Keep the README's "Where this stands" line current; it is the pick-up point.
- **Vocabulary (decided 2026-09-28).** `palette.json` keys are the one set of names; the README ladder table's first column and the token rule names in the theme (`<what> — <key>[, note]`) follow them, and `tools/check.py` fails when the three drift. Neutrals by rung, extending Rosé Pine's `muted`/`subtle`/`text` (the reference ladder in `~/projects/craft/briefs/theme-colour-systems-2026.md`): `ground`, `raised`, `hairline`, `muted`, `comment`, `subtle`, `frame`, `text`, `bright`. Accents by colour: `blue`, `sky`, `peach`, `gold`, `red`, `green`, `magenta` — the last exists only for the ANSI slot, the room has no purple. State backgrounds at the blue-hour hue: `highlight_low`/`_mid`/`_high`. Terminal brights: `<base>_bright`. File order, which the table follows: neutrals and highlights by lightness, accents by family (cool pair, warm pair, then the status colours), brights in ANSI slot order. Why: three vocabularies named the same rungs, and the table had drifted eleven values behind the file (audited 2026-09-18).
- **Hero and logo (decided 2026-09-28, Luca's picks shown live).** The hero is Vesper's card composition with a window frame like the other theme heroes' (rounded, hairline edge, three gray dots, the file name), on the theme's own ground, the code fading right and bottom, the lockup bottom right: `samples/blue-hour.ts` lines 1–33, the current line on `ceiling.off()`. It is not a screenshot: `tools/hero.mjs` colours the sample with the theme's token rules and takes every chrome colour from the theme's own keys, so a colour change regenerates it with one command (the brief found no theme repo keeps its hero current, median three years behind). The logo is the dome: a blue-hour gradient through `highlight_low`, `highlight_high` and `blue` to the `sky` rung at the horizon, a `peach` horizon line, on the `ground` tile, 96 wide of 128. Every hex in `assets/logo.svg` is a rung; `check.py` fails otherwise. Rejected on sight: a bird's-eye plan of the room (charming at 128, dots at 16), a lightness-ladder mark (a menu icon at 16), a lamp-in-a-window mark; three JSX-heavy code stretches ("literally looks like HTML"). The wordmark says "Blue Hour" and rides with the naming pass; regenerating is one command.
