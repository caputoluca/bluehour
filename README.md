# Blue Hour

A dark colour theme for Cursor and VS Code. Flat near-black ground, a neutral lightness ladder that does most of the work, and two restrained accent families: cool for the language, warm for what you put in. The name is provisional (a naming pass is still owed); it comes from the sofa-at-blue-hour blue that became the accent.

**Where this stands (2026-09-27).** The trial is closed as a keep. Seventeen days on real files from 2026-09-10, reviewed 2026-09-27 (HOME-74): "I've been enjoying it, I like it so far", and the little code read "is pretty fine for me to read". The cool-and-dark feeling never arrived, so Night Shift on a sunset schedule and the Paper ladder (v7) close with the trial. Version 0.2.7 is installed in Cursor (`caputoluca.blue-hour-theme`, from the `.vsix`): the 0.2.2 ladder with one change from 0.2.6, a 1px neutral line along the top of the active tab at the line-numbers rung; the record is v9, and each trial note below now carries its decision. Dark+ stays installed and carries the Blue Hour status bar through `workbench.colorCustomizations` in user settings. Next steps, in order: (1) the cleanliness pass in `AGENTS.md`, internal names only, then the ladder table rebuilt; (2) the naming pass, the public name and id, permanent once published, `package.json` `name`/`displayName`/`publisher` ride with it; (3) split this README into a public README and a design-notes file; (4) public GitHub repo with the `.vsix` on a release; (5) Open VSX first, since Cursor reads it, the Microsoft marketplace second. Separate, with the dotfiles task (Linear HOME-75): the Claude Code status line onto the ladder (third trial note), and a dotfiles repo for Cursor settings, keybindings and an extensions list, since Cursor has no Settings Sync. Nothing is pushed anywhere yet; this repo has no remote.

## Trial notes

Noticed while using it on real files, recorded as they come and not acted on; the review decides which of them is worth a version.

- **2026-09-18 — which tab is active is hard to see.** "It's hard to tell which file is currently active on the top bar"; for a plain file "it goes from gray text to white text so that kinda helps, but is also still a bit hard to tell", and for a modified or untracked one "there's not much of a difference, the hairlines around it aren't that prominent enough". The theme file agrees, on two counts. The only cue separating active from inactive is the label: `tab.activeForeground` `#C4C4C4` (L 0.82, Lc 70) against `tab.inactiveForeground` `#929292` (L 0.66, Lc 43), a 0.16 L step, with `tab.activeBackground` and `tab.inactiveBackground` both the ground `#141414` by the flat-ground rule, so there is no second cue. A git decoration then replaces that label colour and outranks it: modified is the gold `#ECCAAD` at L 0.861, *brighter* than the active rung, so a modified background tab reads brighter than the undecorated active one; untracked is the green `#92BE9A` at L 0.76, between the two rungs, so it reads as neither. (That green is `green` in `palette.json` — additions, untracked, diff inserts, ANSI green — and is missing from the ladder table above; noted for the review.) And there is no marker to fall back on: `tab.activeBorderTop` is `#2B2B2B`, the hairline rung, Lc 0.0 against the ground and the same value as `tab.border` and `editorGroupHeader.tabsBorder`, so the active tab's marker is the same hairline drawn between every tab; `tab.activeBorder` is unset. Not settled that it should change at all: the explorer marks the open file well, so the bar is "if we can make this better without going against the theme then yea, otherwise it's not the worst thing ever". The explorer is also the answer to how. It has the cue the tab bar lacks — `list.activeSelectionBackground` `#1E2A37` (L 0.28, C 0.029, hue 251, `blue_dp` in `palette.json`): a background block, one rung up from the line highlight with a trace of the blue-hour hue, and because it is a background a git colour cannot erase it (the gold still reads Lc 74.5 on it). So the theme already ships a state cue that works on the flat ground, and the tab bar is the one place it was not used; whether the ground rule reads a block on the tab strip as the "gray panel" it rules out is the real question, and the fallback is `tab.activeBorderTop` lifted off the hairline rung. **Review, 2026-09-27: the fallback, shipped in 0.2.7.** Checked against six themes' own files (Dark+, Dark Modern, GitHub Dark, One Dark Pro, Vitesse, Vesper): every one marks the active tab with a line or a lifted block, never by label lightness alone; five draw a 1px line, three in their accent and two neutral; the two flat-ground themes both draw one, Vitesse a neutral line in its text colour, and Vesper's 0.03 L lift is the step v5 found invisible. VS Code draws the line at 1px fixed, so a thicker hairline was never a theme option. Tried live through `workbench.colorCustomizations` scoped to `[Blue Hour]`, one flip at a time: the explorer block on `tab.activeBackground`, shown together with git-modified on the blue, "too much blue now and too out there, it should be just chill, subtle"; the line at the frame-text rung `#C4C4C4`, "not Blue Hour at all, too much pop"; the line at the line-numbers rung `#636363`, "feels a bit warm, but it can work". It is zero chroma; the warmth is simultaneous contrast against the blue beside it, and a trace of the blue-hour hue on a 1px line was not tried because the same trace on the whole ground read as nothing. Kept neutral.
- **2026-09-22 — a problem reads as a modified file.** "The problem color and the git modified color is the same i think, so i sometimes get confused that a problem in a file shows it as a modified file." Confirmed in the theme file: `list.warningForeground`, `editorWarning.foreground` and `minimap.warningHighlight` are the gold `#ECCAAD`, and so are `gitDecoration.modifiedResourceForeground` and `stageModifiedResourceForeground`. Errors have the same collision: `list.errorForeground` and `gitDecoration.deletedResourceForeground`/`conflictingResourceForeground` are all the red `#DA827B`. That one matters less, because deleted files mostly leave the explorer and red is reserved for errors and deletions by rule. Also, the theme already disagrees with itself on "modified": the gutter bar `editorGutter.modifiedBackground` is the blue `#8EA7C4`, but the file name is gold. Candidate: make git modified (and stage-modified) the blue `#8EA7C4` (L 0.719, C 0.051, hue 252, WCAG 7.4:1, Lc 52.6 on the ground). The gutter and the file name would then share one colour for "changed", and gold would mean "warning" only. It would also ease the tab-bar note above: a modified tab at L 0.72 sits under the active rung (L 0.82) instead of above it the way the gold does (L 0.86). Cost: blue is already the busiest accent (keywords, focus, badges, links). **Review, 2026-09-27: left as is.** The blue on modified was shown live and read as too much blue. Of the six themes checked, four keep modified and warning in the same warm family and lean on VS Code's default gap, a tan `#E2C08D` (L 0.83, C 0.08) against a yellow `#CCA700` (L 0.74, C 0.15), and only Vitesse moves modified to blue; Blue Hour is the only one where the two are one hex. The gap done on the ladder, modified one rung quieter at `#C4AC98` (L 0.76, C 0.04, Lc 59), would put changed files below plain file names at L 0.82, so they would recede, and the chroma cap means the theme cannot buy the difference back with saturation the way GitHub Dark does. The M badge against a problem count carries the distinction. Reopen if the confusion recurs.
- **2026-09-27 — the Claude Code status line reads plain when there is no countdown.** "When we don't have like a countdown for statusline, it's going to look a bit plain, just white and gray, so that might be needing a fix", offered with "which might not be Blue Hour's responsibility". It is not. The status line is painted by `~/.claude/statusline.sh` in truecolor escapes, not from the theme's ANSI slots, so the theme cannot reach it (the v8 finding in reverse). Its palette was sampled verbatim from the apartment stills on 2026-09-08, before the ladder: the mission in a chrome white `#BBBFC1` bold, phase and gate in the sofa gray `#979AA7`, the countdown in the blue `#758FB1`, the one-day cue in a lamp `#D8927A`, repo and branch in charcoal `#585A60`. The one blue sits on the countdown, so with `countdown` off in `now.json` the line is white and gray by construction. Candidate: put the status line on the ladder, so its colours are the theme's rungs and one accent survives without a countdown. Lives with the script, which is tracked nowhere (it sits loose in `~/.claude/`; `now.json` is in the home repo, the script is not), so the dotfiles task (HOME-75) is its home, not this theme. The countdown is on today (FE Manila, 2026-10-25), so the plain read arrives when that gate passes. For the record, its colours already sit near the ladder: the countdown blue `#758FB1` is hue 255 at chroma 0.059, within 3 degrees and 0.01 of the theme's blue `#8EA7C4`, one rung darker. **Review, 2026-09-27:** recorded; nothing for the theme, the slice belongs to HOME-75.

## The system

Three ideas, borrowed from the room the palette came from:

- **The ground is the floor.** One flat near-black everywhere: editor, sidebar, tabs, panels, status bar. Hairlines separate areas, not gray panels. The near-black is zero chroma. 0.2.1 tried a trace of the blue-hour hue in it (chroma 0.009) against "lifeless"; a day on each settled it the other way: the black was the one wanted, and the dullness was in the accents, not the ground.
- **Cool is the language, warm is what you put in.** Keywords and tags are a restrained blue; calls and types a lighter sky. Strings are the lamp peach; numbers, constants and escapes a quiet apricot. That is the whole colour budget: two families, four colours.
- **Everything else reads by lightness.** Names are the brightest neutral: variables, properties, parameters and plain text sit one rung under white. Punctuation and operators step down, so structure recedes and names come forward. Comments a quiet gray. Line numbers and guides lower still. On a line the rhythm is neutral name, sky call, neutral name: what Dark+ gets from blue and yellow, at a fraction of the chroma.

No italics, no bold except Markdown headings. Red exists only for errors, deletions and merge conflicts; it never appears in syntax.

## The ladder

Every value was designed in OKLCH (perceptual lightness) and checked with `tools/colortool.py` against the ground for WCAG ratio and APCA contrast. None is a photograph sample; the room gave the hue families, the ladder gave the values.

| role | hex | OKLCH L | chroma | APCA Lc |
| --- | --- | --- | --- | --- |
| ground | `#141414` | 0.19 | 0 | — |
| line highlight, inputs | `#1D1D1D` | 0.23 | 0 | — |
| hairlines, guides | `#2B2B2B` | 0.29 | 0 | — |
| line numbers, inactive, the active tab's line | `#636363` | 0.50 | 0 | 21 |
| punctuation, operators, inactive tabs, breadcrumbs | `#929292` | 0.66 | 0 | 43 |
| comments | `#808080` | 0.60 | 0 | 34 |
| frame text you read: explorer, status bar, headers | `#C4C4C4` | 0.82 | 0 | 70 |
| names, plain code text | `#D4D4D4` | 0.87 | 0 | 80 |
| carets, bright white | `#E8E8E8` | 0.93 | 0 | 92 |
| keywords, tags | `#8EA7C4` | 0.72 | 0.05 | 53 |
| calls, types, decorators | `#A9D1EA` | 0.84 | 0.055 | 75 |
| strings | `#E6A68A` | 0.78 | 0.085 | 61 |
| numbers, constants, escapes, warnings | `#ECCAAD` | 0.86 | 0.055 | 77 |
| errors, deletions | `#DA827B` | 0.70 | 0.11 | 47 |

Targets came from the colour-systems brief: body text Lc ≥ 75, secondary ≥ 60, comments and punctuation 45–60. Comments sit a little under that floor on purpose, to be read second. 0.1.0 had names at 70, under the body-text floor; 0.2.0 moved them to 80. Frame text you read sits one rung below the code; frame state (inactive tabs, breadcrumbs, line numbers, placeholders) below that. `palette.json` holds the same values by role name.

## Working on it

- **See it:** open this folder in Cursor and press F5, or from a terminal `cursor --extensionDevelopmentPath="$PWD" "$PWD/samples"`. The `samples/` folder pins the theme in that window only (`samples/.vscode/settings.json`), so the main window keeps whatever it had. Ten sample files cover TypeScript, TSX, Python, YAML, Markdown, JSON, shell, CSS, Prisma and SQL.
- **Tweak it:** each role is one hex in `themes/blue-hour-color-theme.json`, repeated wherever the role appears. Change a role with a find-and-replace on its hex, then Cmd+R in the dev-host window (theme-file edits usually apply live; a reload never hurts). `Developer: Inspect Editor Tokens and Scopes` on any word shows which rule coloured it.
- **Check a colour:** `python3 tools/colortool.py '#181B1F' '#E6A68A'` prints OKLCH, WCAG and APCA against the ground.
- **Install it for real:** `npx @vscode/vsce package` then `cursor --install-extension blue-hour-theme-0.2.1.vsix`. Switch with Cmd+K Cmd+T; Dark+ stays installed.
- **Leak check before publishing:** with the theme active, run `Developer: Generate Color Theme From Current Settings`; every commented-out line is a colour still falling back to stock VS Code.

## Publishing, when the time comes

Cursor's extension panel reads the Open VSX registry, not Microsoft's marketplace, so a marketplace-only theme never shows up in Cursor. Order: Open VSX first (Eclipse account, publisher agreement, namespace, `ovsx publish`), the Microsoft marketplace second (`vsce publish`; its Azure token path retires 2026-12-01, Entra auth after), and the `.vsix` on a GitHub release for `cursor --install-extension`. The published id `publisher.name` is permanent, which is why the naming pass comes before this step. Sources and grades: `~/projects/craft/briefs/vscode-theme-authoring-2026.md`.

## How it got here

Four versions in one evening and a fifth the next, all on the same ten sample files. The record matters more than the files, so the dead ones were deleted and the reasons kept:

1. **v1 — verbatim room swatches on a monochrome scheme.** Read flat: three near-whites within a hair of each other, and the sampled near-black had a blue cast. Photographed paint and fabric are low in chroma; on a screen next to Dark+ they wash out.
2. **v2 — Dark+'s role structure with the nearest swatch for each role.** Read as "colours thrown together"; the baby-blue variables were the clearest case of a swatch with no reason to be on that word. A mapping is not a design.
3. **v3 — the blueprint done properly, six full hues on a designed ladder.** Solved reading ("100x easier") and produced a generic theme, because six full hues is Dark+'s own recipe. No specialness.
4. **v4 — the same ladder, two accents, flat near-black.** "Really nice and cool." Kept as 0.1.0.
5. **v5 — same palette, names up a rung, calls onto the sky, frame lifted.** The 0.1.0 trial: "really clean and nice" but hard to read, and unsure whether that was habituation. Probes on the same file settled it. Vesper (two hues, white text, Lc 107) was also hard; GitHub Dark read easily; One Dark Pro was "too much going on". Contrast did not track the verdicts, hue count did, and a new many-hue theme reading fine on first sight ruled out habituation: Luca reads by hue, and the line had no cues ("my brain is searching for hints via the colors and not finding any"). The colour-systems brief then corrected the first fix: four of seven good themes leave variables plain and hue functions instead. Tried on names and rejected: lavender ("a bit better", wrong vibe: the room has no purple), tan, cream; the ladder's top white ("jarring/laggy when I scroll") stepped down to Dark+'s own `#D4D4D4`. Calls moved from white to the sky, shared with types as Vesper and GitHub Dark do: "a bit better, but now too much blue". Two ways out of the blue were tried and rejected: keywords to a neutral (Vesper's move) and calls to the apricot ("calls should stay on blue, it's the main colour"). Back to calls-on-sky: "honestly isn't that bad". Frame: explorer text, inactive tabs and breadcrumbs sat far below Dark+ (Lc 43 and 21 against about 75 and 40) and came up; both carets and the activity-bar badge lost the peach, so warm in the frame now only means attention (warnings, ANSI yellow, the Claude Code prompt). The ground came last, as 0.2.1: a lightness step of +0.03 L was invisible ("looks the same to me"); the real complaint was "lifeless", which is what a zero-chroma ground reads as, so the three bottom rungs got a trace of the blue-hour hue at the same lightness (C 0.009, H 256), the v1 blue cast done on the ladder instead of sampled. Verdict: "a bit less dull, a bit more blacker", kept. The status bar, section headers and titles went from the comment rung to the explorer rung at the same time. Two hybrids (this frame with Dark+ code, and with GitHub Dark code) were built and shown: both read "bright and too dark at once" on `#141414`, a ground darker than either syntax set was designed for. Deleted; the lesson is the ground, not the hybrids.
6. **v6 — the ground back to the 0.2.0 black.** A day in the home repo on 0.2.0, with 0.2.1 open in another window: the tinted ground was "a little bit too blue, not black" and the black was "growing on me", while the dull, faded feeling was still there on the black. That locates it in the accents, not the ground. The cool accents run at about half of Dark+'s chroma and a third of GitHub Dark's (keywords C 0.05 against 0.11 and 0.16; strings, at 0.085, match both), every accent is a pastel, and calls sit within 0.03 L of plain names, so the only cue separating a call from a name is a weak hue. The three bottom rungs went back to `#141414`/`#1D1D1D`/`#2B2B2B`; the 0.2.1 frame-text lift stayed. Kept as 0.2.2. The open question is whether the understated read is the charm or the flaw: the charm is the hue count (two families, one flat ground), which the v3 record ties to specialness; chroma is a separate dial that had never been tested on its own. Tested as 0.2.3 the same evening: the four accents at the same lightness and 1.4 times the chroma (`#8EA7C4` → `#84A8D0`, `#A9D1EA` → `#9AD3F6`, `#E6A68A` → `#F79E76`, `#ECCAAD` → `#F6C79E`; every Lc unchanged, so only the pop moved). Verdict: "isn't bad", but "looks a lot like other themes now with bright poppy colors", "less unique or special, just like a blue theme now instead of a monochrome one". Reverted, never released. So chroma is part of the identity after all, not only the hue count: the cool family covers keywords, calls, types and decorators, most of the coloured tokens on a line, and lifting it makes a blue theme by a different road than v3's six hues. Third time the pattern has held: pushed toward pop it reads generic, restrained it reads nice. Closed: the understated read is the charm and the faded feeling is its price. A half step (1.2 times) was not tried, because the 0.03 L ground step being invisible says small steps here read as nothing.
7. **v7 — paper white: a trace of warmth in the neutrals.** The worry after locking the black and the low chroma: "is it gonna be depressing to be looking at such cool colors all day... very nice and aesthetic but also a little bit lonely". Checked rather than guessed: Valdez and Mehrabian (1994) and Wilms and Oberfeld (2018) find brightness and saturation drive mood far more than hue, blue among the most pleasant hues, dark plus desaturated the low-valence corner. So the effect is real, and it comes from the ground and the chroma, not the blue, and both of those had just been chosen on purpose. The cheapest counter, the move every warm dark theme makes, is the neutrals: the six text rungs from the caret white to the line numbers at hue 70 (between the gold and yellow, the room's warm family), chroma well under 0.01, every Lc unchanged, ground and accents untouched. Built at 0.010 first: "does feel a bit more warm and happy", "more approachable and warm and kinda nicer to you when you read it", but markdown prose "not original white and kinda orange-ish", because prose is a solid mass of one colour and shows a tint about twice as strongly as code broken by accents. Halved to 0.006 and committed as 0.2.4. Luca on the two: "the original one was a real bold/unique statement and oddly chill", "this one is a bit more approachable and warm and kinda nicer to you when you read it", "they are both good", and handed the call over. The first call was warm, on the argument that the reading verdict outweighs the statement verdict for a tool read all day. It did not survive the hour. At 0.006 prose still read "a little bit orange, not usual, a little bit odd", and a table of twenty dark themes run through the checker showed why: every warm-text theme (Gruvbox, Kanagawa, Flexoki, Ayu, Zenburn) sits at hue 80 to 107, paper yellow, while this tint rounded to hue 60, the orange edge; only Dark+ and Vesper ship untinted gray at all. Shifted to hue 95 at the same chroma as 0.2.5 (`#E9E8E4`, `#D5D4D0`, `#C5C4C0`, `#93928E`, `#81807C`, `#64635F`; every Lc unchanged): that is what "Blue Hour Paper" was. Then "I'm a little bit sad we lost the old super unique and oddly chill one", and the call was reversed: the lonely worry was a projection from a paper, "growing on me" was a day of observation, and observed beats projected. The same table answered "why not cool and brighter, like GitHub Dark": cool text at hue 250 sits 14 degrees from the calls' sky, so the name-to-call cue Luca reads by nearly vanishes (warm is 141 degrees away); brighter text had already lost in v5; and cool plus blue is the 0.2.3 verdict by another road. For a fair look, both were packaged as separate themes so the picker (Cmd+K Cmd+T) flipped the same file live, no reload, with the home window still on the gray build beside it. Verdict: "a tiny yellowish filter over everything, almost like I'm wearing very weak blue light glasses", "almost like night shift from the iPhone"; the main difference showed in the Claude Code terminal, whose ANSI whites carry the tint; gray "more sharp and crisp and more of a statement", Paper "a bit more warm and nice and I feel some warmth"; "I literally can't tell which one I like better, they are honestly very similar and I think it's in my head". It is: the eye adapts a uniform cast away within minutes, so what remains is the filter look next to a neutral macOS. Gray is the lock; Paper is documented here, not shipped. Warmth in the evening is the OS's job, not the theme's: Night Shift on a sunset schedule is the same cast, every app, only at those hours; Paper was Night Shift at noon in one app. Kept: the 0.2.2 ladder, shipped as 0.2.6.

8. **v8 — the terminal chrome, no version.** Two days into the trial the faded feeling had a location: not the editor but the Claude Code terminal, the spark top left and the "auto mode on" line, the two things looked at most of the day. Both are painted from the theme's ANSI slots, because Claude Code is on its `dark-ansi` theme: the spark is the bright-red slot, which the theme had derived as a lighter rung of the error red (same hue, 25, so the spark had been a pale error red all along, by Claude Code's mapping rather than the theme's choice), and the auto mode line is Claude Code's warning colour, the yellow slot, the gold. Claude Code's own palette paints them at chroma 0.13 and about 0.17; the slots deliver 0.10 and 0.055. Tried live through `workbench.colorCustomizations` scoped to `[Blue Hour]`, two slots, no rebuild, no reload: the lamp hue at 1.4 times ("kinda looks the same"); the lamp hue two rungs darker at full chroma ("orange, doesn't match the theme"); the original hue pushed in four steps to the sRGB edge, each step a rung darker to buy chroma, since at that hue the screen cannot be bright and saturated at once ("one more" twice, then "that's red"); then the 0.2.3 values, lamp and gold at 1.4 times ("we've moved backwards, the initial was a bit better"). Fifth time the pattern has held, now on two glyphs instead of a page: under about 1.4 times reads as nothing, 2 times reads as off-theme, and there is no rung between. Then the other route: Claude Code reads custom themes from `~/.claude/themes/<slug>.json`, a base theme plus per-key overrides, picked in `/theme`; one was built with base `dark-ansi` (inherits the theme's slots) and only the spark overridden to Claude's own terracotta: "looks the same tbh". Closed: the slots stay as designed, Claude Code stays on `dark-ansi`, and the faded feeling in the terminal is the same price the editor pays. Kept from it: the spark's key exists, so if it ever matters it gets its own colour there, not through the bright-red slot every other tool shares.
9. **v9 — the trial review; the active tab gets a line (0.2.7).** Seventeen days on real files instead of seven, reviewed 2026-09-27: a keep, "I've been enjoying it", the little code read reading fine, and the cool-and-dark feeling never arrived, which is what v7 predicted once the eye adapts the cast away; Night Shift and Paper close with the trial. Three trial notes went to the review. The active tab: the explorer block and git-modified on the blue, shown together, "too much blue"; the check across six themes' files found five of six draw a 1px line and both flat-ground themes do; the line at `#C4C4C4` "too much pop", at `#636363` "a bit warm, but it can work", and that is the one change in 0.2.7. Warnings and git-modified sharing the gold: left, four of six themes ship the same collision and the quieter modified would recede below plain file names. The Claude Code status line reading plain without a countdown: the script's own truecolor palette, not the theme's, so it goes with the dotfiles task. Method: every candidate went on through `workbench.colorCustomizations` scoped to `[Blue Hour]`, one at a time after the first pair confounded the verdict, flipped live with no rebuild, and the settings file went back to its pre-session bytes once 0.2.7 was installed.

Two chrome-only fallbacks were also built and shown (Dark+ code with this frame; Dark+ with only the status bar changed) and are documented here so nobody rebuilds them: they read fine but "not different enough to switch". Research behind the blueprint: `~/projects/craft/briefs/theme-colour-systems-2026.md` (seven themes' own role mappings, the reading evidence, the ladder science).
